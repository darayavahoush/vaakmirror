# VaakMirror API

FastAPI + PostgreSQL backend for VaakMirror. Stores game session results
tagged by the phonetics taxonomy (place/manner/voicing), and turns them into
the therapist/parent dashboard (category accuracy, flagged gaps, weekly
progress) and the oromotor exercise assignment system.

Matches the stack convention from `breathquest` (FastAPI + PostgreSQL) so
this can eventually point at the same database instead of standing up its
own — see the note in the frontend README about that.

## Setup

**1. Get Postgres running.** Two options — use whichever's less friction for you:

- **Local Postgres you already have** (e.g. via Homebrew): create the role
  and database:
  ```
  createuser -s vaakmirror
  createdb -O vaakmirror vaakmirror
  psql postgres -c "ALTER ROLE vaakmirror WITH PASSWORD 'vaakmirror';"
  ```
  This uses the default port 5432, matching `.env.example`.

- **Docker** (if you'd rather not touch your local Postgres):
  ```
  docker compose up -d
  ```
  This runs on port 5433 instead of 5432, specifically to avoid clashing
  with a Postgres you might already have running locally. If you use this
  path, change the port in `.env` from 5432 to 5433.

**2. Python environment:**
```
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**3. Environment file:**
```
cp .env.example .env
```

**4. Create tables + seed the exercise library and a demo child:**
```
python -m app.seed
```

**5. Run the API:**
```
uvicorn app.main:app --reload --port 8000
```

API docs (auto-generated by FastAPI) are then at
`http://localhost:8000/docs` — useful for poking at endpoints directly
before wiring up frontend calls.

## Data model

- **Child** — a profile the games/dashboard are scoped to. No auth or
  multi-therapist support yet — the seed script creates one demo child
  (id `1`) and the frontend currently just points at that id directly.
- **GameSession** — one play session of one game (Mirror Mirror / Tongue
  Tamer / Lip Sync Hero).
- **Attempt** — one scored attempt within a session, tagged with
  place/manner/voicing where applicable (Tongue Tamer attempts don't carry
  a phoneme tag, since its targets are movements, not sounds).
- **ExerciseTemplate** — the static oromotor video library.
- **ExerciseAssignment** — links a child to an exercise template with a
  status (assigned / in_progress / completed).

## Dashboard aggregation

`GET /children/{id}/dashboard` does the actual "diagnostic layer" work: it
groups attempts by manner/place/voicing, computes accuracy per category,
and flags any category with at least 5 attempts and under 55% accuracy —
which is what turns raw per-sound logs into the "here's the pattern to work
on" view instead of a flat table. Thresholds (`MIN_ATTEMPTS_FOR_GAP`,
`GAP_THRESHOLD` in `app/routers/dashboard.py`) are reasonable starting
points, not clinically validated — worth revisiting with a speech
therapist's input once there's real usage data to look at.

When a gap is flagged and a matching exercise exists in the library, the
dashboard **automatically creates that assignment** (not just a suggestion
string) — so loading the dashboard is what triggers the "here's your
homework" step, not a separate manual click. This is a side effect on a GET
endpoint, which isn't conventional REST; the reasoning and the idempotency
guard against duplicate assignments are documented in
`_ensure_assigned()` in `app/routers/dashboard.py`.

## Not done yet

- **No auth.** Anyone who can reach the API can read/write any child's
  data. Fine for local development, not fine to deploy as-is.
- **No Alembic migrations** — schema changes currently mean re-running
  `Base.metadata.create_all`, which won't alter existing tables. Worth
  introducing Alembic before this holds real data you can't afford to lose.
- **Single hardcoded child.** No UI yet for creating/switching between
  children — the API supports multiple, the frontend doesn't expose it.
